## Где находится реализация

`fast_api_server_v2` (`5e7a843`) ещё не содержит весь пакет уточнений. Он реализован командой в `hackathon-clarifications` (`8cad90f`), одним коммитом поверх этой ветки. `frontend_v2` основана на `8cad90f`, сохраняет FAQ и остальные командные изменения. Дополнительные изменения этой задачи затрагивают только Frontend и обязательный журнал; Java, ML, исходные OpenAPI и PDF-шаблоны не редактировались.

## Сверка всех четырёх пунктов

| Требование | Реализация и проверка |
| --- | --- |
| Инструкция после покупки, источник, «Не помогло», статус передачи | Источники выводит `SourcesList`. Только серверный `Session.support_topic` включает действие для доставки ключа, активации или возврата. Кнопка отправляет обычное сообщение с `text: "Не помогло"` через текущий контроллер, без нового URL или поля action. Решение о передаче принимает Java; UI показывает его после GET handoff. При открытом обращении кнопка скрыта, ввод и черновик сохраняются. |
| Цена и `available=false` | Карточка показывает цену и исходный статус. Явный `selectable:false` блокирует выбор независимо от availability; `true` разрешает попытку. Для исторической карточки без необязательного флага решение проверяет POST selection, а Frontend не вычисляет разрешение из цены/availability. Подпись не обещает срок поставки. Проверены ответ 200 и OFFER_CHANGED с явным подтверждением новой версии. |
| КП → одобрение → счёт, скидка и изменившиеся условия | Сохранены отдельные действия «Сформировать КП» и «Одобрить КП и получить счёт»: второе последовательно вызывает существующие approval и invoice-drafts. До явного согласия счёт не запрашивается. Повтор использует тот же quote_id. Цена, скидка и итог приходят в price_terms; Frontend их только форматирует. Это цена за единицу позиции, а сумма по количеству находится в КП. OFFER_CHANGED/QUOTE_SUPERSEDED отменяют использование старого КП, QUOTE_APPROVAL_REQUIRED возвращает действие одобрения. |
| Менеджер: две новые причины, история и условия | Актуальный manager OpenAPI содержит instruction_failed и payment_deferral. Подписи — «Инструкция не помогла» и «Отсрочка оплаты». Доступный GET назначенного обращения возвращает сообщения и sales_context: позицию, версию КП, количество, одобрение, цену, скидку и agreed_total. UI показывает только эти данные. Отдельный журнал событий не выдумывается. |

## Дополнительные исправления Frontend

- Убрано вычисление разрешения выбора по availability при отсутствии selectable; явное серверное запрещение имеет приоритет.
- «Не помогло» не показывается при подтверждённом открытом обращении. Отправка сохраняет обычную идемпотентность/recovery и не стирает набранный черновик.
- Суммы price_terms обозначены как цена за единицу; нет пересчёта скидки, налогов или количества на Frontend.
- После QUOTE_APPROVAL_REQUIRED можно явно одобрить КП повторно вместо бесконечного повторения запроса счёта.
- Guard sales_context проверяет quantity >= 1 согласно OpenAPI.

Снимки public/manager контрактов совпадают с исходными YAML этой ветки, generated types актуальны. Новые маршруты или поля не добавлены.

## Ограничения совместной приёмки

- Команда должна согласовать и настроить CHAT_DISCOUNT_PERCENT (по умолчанию 0, максимум 5). Frontend не определяет наличие купона, право на скидку или её процент.
- PDF счёта по текущему контракту предназначен для согласования и использует справочные реквизиты. Источник номера, реквизиты сторон и условия платёжного выпуска требуют отдельного подтверждения; Frontend не объявляет такой PDF окончательным платёжным документом.
- Успешные браузерные перехваты HTTP/SSE подтверждают Frontend и обработку DTO. Живые Java/БД/ML, релевантность загруженных инструкций и скидка/приоритет отсрочки должны пройти совместную серверную приёмку. В этой задаче сервер и модель не запускались и не изменялись.
