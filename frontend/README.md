# Frontend консультанта Softline

React + TypeScript + Vite. Рабочий каркас клиентского чата с POST/fetch SSE,
историей, восстановлением, карточками, источниками и выбором предложения.
Два раздела одного приложения: клиентский консультант и менеджерское рабочее пространство.
Dark Premium и светлая Softline: единая геометрия, аккуратное glass-оформление,
контрастные карточки и источники, короткие анимации с reduced motion.
[Дизайн-система и визуальные проверки](docs/design-system.md).
[Сверка с официальным брендбуком](docs/brandbook-review.md).
[Повторный аудит требований и карта соответствия](docs/requirements-audit.md).
[Итоговая готовность и состав публикации](docs/release-readiness.md).
[Инструкция Backend-разработчику](docs/backend-integration.md).

## Окружение

Рекомендуется Node.js 24 (проверено на 24.22.3) и pnpm 11.25.0.
Допустимые версии Node указаны в package.json; версия для менеджеров Node — в .node-version.
Зависимости закреплены в pnpm-lock.yaml.

Все команды ниже выполняются в frontend/:

```sh
pnpm install --frozen-lockfile
pnpm dev:mock
```

Адрес: http://127.0.0.1:5173. Моки запускаются до React; Backend и ML для этого режима не нужны.

В текущей среде Codex Node существует вне обычного PATH. На время терминальной сессии
можно использовать имеющийся runtime (это не меняет файлы настройки оболочки):

```sh
export PATH="$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/bin/fallback:$PATH"
pnpm dev:mock
```

Для независимой работы из VS Code установите совместимый Node своим менеджером версий
и обеспечьте доступность pnpm. Скрипты не зависят от абсолютного пути runtime Codex.

## Работа с Backend

```sh
pnpm dev
```

В этом режиме моки не подключаются. Vite проксирует `/api` и `/health` на
http://127.0.0.1:8080. Другой адрес задаётся переменной BACKEND_PROXY_TARGET:

```sh
BACKEND_PROXY_TARGET=http://127.0.0.1:8090 pnpm dev
```

Это серверная настройка разработки, не ключ API. Origin сохраняется; его разрешение и
Secure cookie нужно проверить совместно с Backend. На стенде Caddy раздаёт dist/,
браузер обращается к API того же HTTPS origin. Секреты в переменные VITE_* не помещаются.

## Сценарии моков

Все ответы синтетические, что явно указано в интерфейсе. Существующие SSE-примеры
импортируются из ../contracts/examples/ без изменения исходных файлов.

| Ввод | Сценарий |
| --- | --- |
| Стартовая подсказка «Знаю продукт» | Уточнение; следующий вопрос приводит к карточке |
| «Подобрать решение» / текст с «50» | Рекомендация и выбор карточки |
| Текст с «вопрос», «документ» или «оплата» | Демонстрационный справочный ответ с источником |
| «Ошибка модели» | MODEL_TIMEOUT с доступным повтором; повтор успешен |
| «Обрыв ответа» | Поток закрывается до done; GET/polling восстанавливает полный ответ |
| «Подбор без цены» | Карточка с price=null |
| «Подбор: изменение предложения» | OFFER_CHANGED при выборе; актуальную карточку нужно подтвердить |
| «Лимит» | HTTP 429; текст возвращается в редактор |

Мок-сервер сохраняет историю в localStorage браузера под softline:mock:server.
Перезагрузка после завершения хода сохраняет историю и выбор. Если перезагрузить
страницу во время обычной генерации, остановившийся браузерный мок помечает ход failed,
а выданный фрагмент partial. Это имитация прерывания, а не работа фонового ML-процесса.

Кнопка «Новый диалог» создаёт новую сессию. Хранение моков и настоящей сессии разделено.
Не используйте реальные клиентские данные в демонстрационном режиме.

## Два пользовательских раздела

- `/#/chat` — существующий клиентский чат; корень `/` также открывает его.
- `/#/manager` — очередь демонстрационных обращений в mock-режиме.
- `/#/manager/DEMO-1024` — пример открытого обращения.

Разделы используют одну шапку, токены и навигацию. После первого открытия чат остаётся
смонтированным при переходе в менеджерский раздел: черновик и активный POST/SSE не теряются.
Прямое открытие менеджера не создаёт клиентскую сессию. Мобильная версия показывает
очередь или обращение с возвратом, без выезжающей панели.

В `pnpm dev` менеджерский интерфейс подключён к подтверждённым маршрутам:
очередь limit=50/offset, polling каждые 5 секунд, claim, чтение назначенного контекста,
ответ с message_id и resolve. Токен вводится в интерфейсе, хранится только в памяти
до выхода/перезагрузки; он не попадает в URL, localStorage/sessionStorage или VITE_*.
401 завершает доступ. В статусном списке шириной 210px доступны «Все», «Ожидают»,
«В работе», «Завершённые» → queued/in_progress/resolved. Поиск и фильтр работают
только по загруженной странице; общего количества API не возвращает.

Детали и действия ответа/закрытия доступны после успешного GET назначенного обращения.
queued можно взять в работу через claim. По одному in_progress владение не угадывается.
Повтор явной отправки того же текста после ошибки использует прежний message_id.
Переходы отображаются по серверному ответу. Закрытый контекст доступен только для чтения.
CaseTimeline показывает имеющиеся сообщения, не придумывает журнал events или даты.

Ручной передачи клиента нет. После обычного done/восстановления читается session/handoff;
при открытом обращении polling обновляет его статус и историю той же сессии без
блокировки редактора. sender=manager подписывается как специалист. После resolved
следующий запрос снова обрабатывает Java/ИИ. Текст, цена и insufficient_data не
используются для самостоятельного решения о передаче.

В `dev:mock` сохраняется изолированная очередь из четырёх синтетических примеров,
без реальной отправки/назначения. Полная цепочка операций дополнительно проверяется
через `pnpm test:api-browser` в обычном API-режиме с перехватами HTTP по контракту;
это не испытание настоящего Java. Старое хранилище ручных передач не используется.

## Темы

Переключатель в шапке меняет только палитру и официальный вариант логотипа.
По умолчанию сохранён Dark Premium; выбор `dark`/`light` хранится под
`softline:theme:v1` в localStorage и применяется в index.html до React/CSS.
Без доступа к хранилищу переключение работает в текущем посещении.
Изменение темы в соседней вкладке синхронизируется через storage event.
Общая геометрия, размер логотипа, типографика, анимации и расположение элементов
одинаковы. На узком экране разделы представлены иконками с доступными названиями.

Тёмный оригинал — белый SVG из EPS; светлый — исходный цветной PNG 2000×442
из брендовых материалов, без перерисовки/перекрашивания. Оба сохраняют пропорции
через object-fit: contain в одинаковой области. Reduced motion отключает движение,
reduced transparency и fallback без backdrop-filter используют плотные поверхности.

## Коммерческие документы

После выбора при quotes_enabled=true форма отправляет POST quote-drafts с ровно
двумя JSON-полями: customer_name (1..160 символов), quantity (целое 1..99999).
Количество относится к единице выбранной позиции, а не числу пользователей лицензии.
Для одной лицензии на 50 пользователей по умолчанию quantity=1. ИНН/КПП и расчётов нет.
Тип запроса получен из актуального QuoteRequest, ограничения соблюдаются в форме/API.
Ответ проверяется по MIME application/pdf и сигнатуре %PDF-; имя файла безопасное.
POST не повторяется автоматически. Ошибки оставляют форму; OFFER_CHANGED позволяет
обновить выбор. Размонтирование/новый ход/смена выбора отменяют незавершённую операцию.

В dev:mock PDF статический и маркированный, без коммерческой силы. Реальный PDF
должен вернуть Java; сам Java и настоящий документ в этом окружении не проверялись.
Счета в обоих новых OpenAPI отсутствуют. Только в mock после выбора есть изолированный
демопредпросмотр формы счёта: без HTTP, скачивания, итоговой суммы и расчёта НДС.

## Проверки

```sh
pnpm check
pnpm test:e2e
```

check последовательно проверяет актуальность API-типов, TypeScript, ESLint,
Vitest и production-сборку. Unit/integration-тесты работают через MSW в Node.
Браузерные тесты Playwright проверяют десктоп и мобильную ширину через dev:mock.
Тестовый сервер использует порт 5183 и не останавливает приложение разработчика на 5173.
Порт можно переопределить через FRONTEND_TEST_PORT.

По умолчанию Playwright использует установленный Google Chrome в headless-режиме
с отдельным временным профилем. Если Chrome отсутствует, можно установить тестовый
Chromium локально для проекта и выбрать его:

```sh
PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright pnpm exec playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=.cache/ms-playwright PLAYWRIGHT_CHANNEL=chromium pnpm test:e2e
```

Browser storage и сетевые моки тестов изолированы от обычного профиля браузера.
Скриншоты и трассы тестов находятся в test-results/ и исключены из Git.

```sh
pnpm api:generate
pnpm api:check
pnpm build
pnpm preview
```

build создаёт dist/. Production JS не включает обработчики MSW, а production public/
не копирует mockServiceWorker.js. preview показывает настоящую сборку и требует
доступного same-origin Backend для работы чата; моки поддерживаются в dev:mock.

## Структура и решения

- app/ — запуск, общие стили и граница ошибок React.
- pages/chat/ и pages/manager/ — клиентский экран и рабочее пространство менеджера.
- features/chat/model/ — reducer и контроллер сессии, идемпотентности и восстановления.
- features/chat/ui/ — ввод, процесс обработки и системное уведомление handoff.
- features/handoff/ — polling статуса клиентского handoff и изолированные демопримеры.
- features/quote/ — скачивание по существующему PDF-контракту.
- entities/ — карточки, источники и модель демообращения и CaseTimeline (форма DTO менеджерского API пока неизвестна).
- shared/api/ — сгенерированные типы, адаптер, проверки JSON, HTTP и SSE.
- mocks/ — MSW и сохранение синтетической истории; только разработка/тесты.
- tests/e2e/ — сценарии браузерной проверки.

Токен доступа хранится только в серверной HttpOnly cookie. UUID сессии — в localStorage;
незавершённый запрос и полученные ID — временно в sessionStorage текущей вкладки,
до успешного завершения или замены запроса. Доступность Web Storage не обязательна:
при отказе используется память, но восстановление после перезагрузки ограничено.

Ответы выводятся как текст без HTML/Markdown-инъекций. Ссылки допускают только HTTPS
без учётных данных. Суммы не вычисляются через JS number. Нет прямых обращений к ML
и клиентских ключей. Настоящие КП создаёт сервер; счета требуют отдельного согласованного контракта.
Для окончательной приёмки нужен совместный прогон с доступным Java и токеном менеджера.

Форматы определяют неизменённые входные [public](contracts/public.openapi.yaml) и
[manager](contracts/manager.openapi.yaml) от Backend (см. [происхождение](contracts/README.md)), поведение —
[архитектура](../ARCHITECTURE.md). [Вопросы интеграции](docs/backend-questions.md)
зафиксированы отдельно, включая небольшой адаптер типов генератора.


## UX перед интеграцией

Доступное имя textarea — «Ваше сообщение», видимая метка скрыта; placeholder —
«Напишите сообщение...». Пустой ввод занимает около 70 px вместе с кнопкой, растёт
по содержимому до 160 px высоты textarea; свободная область фокусирует ввод.
Короткие текстовые пузыри компактны, длинные ограничены 72ch и доступной шириной;
карточки/источники сохраняют размеры. Круглая кнопка со стрелкой и title появляется
при скрытом конце истории, занимает отдельный ряд над composer и не накладывается
на текст. IntersectionObserver отслеживает конец при стриминге/resize/смене раздела;
контроллер и сохранённое состояние диалога не менялись.

Команды ручной фиксации/отправки и полный список проверенных файлов — в
`docs/release-readiness.md`. Автоматической публикации или деплоя нет.

## Проверки интеграции

pnpm check — оба входных API, TypeScript, ESLint, unit и build.
pnpm test:e2e — визуальные/функциональные сценарии mock-режима, две темы/mobile.
pnpm test:api-browser — обычный API-режим на порту 5185 с контрактными перехватами HTTP:
Bearer, пагинация/polling/401, claim/reply/resolve, handoff/история/черновик, PDF/ошибки.
Отчёты разделены: test-results/ и test-results-api/; оба каталога исключены из Git/ESLint.
Runtime- и schema-проверки не заменяют прогон настоящего Spring Boot/ML.

Входные OpenAPI закреплены в frontend/contracts; общий contracts/ пока старый и
не перезаписывался. api:generate/api:check используют оба новых файла, а не старую копию.
