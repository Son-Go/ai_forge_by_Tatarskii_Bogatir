# План бэкенда

[Архитектура команды](../ARCHITECTURE.md) задаёт требования. [Публичный контракт](../contracts/public.openapi.yaml), [внутренний контракт](../contracts/internal.openapi.yaml) и [примеры SSE](../contracts/examples/) задают форматы для интеграции.

1. **Сессии и журнал.** Реализовать сессионную cookie, проверку `Origin`, сохранение реплики до поиска, резервирование хода, повтор и восстановление по GET. Применить миграции PostgreSQL.
2. **Импорт.** Загружать XML или gzip потоково и активировать только проверенный снимок. Проверить замену версии, неизменившийся фид и отказ импорта на локальном снимке.
3. **Поиск.** Извлечённые в ML требования передавать в SQL-поиск по закреплённой версии. Сверять лицензию, платформу и наличие. Для запроса без точного совпадения проверить семейство, уточнение и подтверждённые альтернативы.
4. **SSE и интеграция.** Связать `interpret`, поиск и `compose`. Сохранять каждый проверенный блок перед выдачей. Пройти обрыв, таймаут, повтор и смену каталога в существующей сессии.
5. **Стенд.** Подключить сборку фронтенда и FastAPI в сети Compose. Проверить HTTPS, запуск после рестарта, фид с VPS и холодный запрос к модели.

Каркас включает настройки запуска Java и PostgreSQL, маршруты health и начальную миграцию. Этапы выше описывают прикладную реализацию.
