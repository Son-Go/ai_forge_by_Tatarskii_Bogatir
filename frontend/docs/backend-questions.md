# Вопросы к Backend

Основной источник: `../../ARCHITECTURE.md`, публичный формат: `../../contracts/public.openapi.yaml`.
Документ фиксирует вопросы интеграции; контракт и архитектура не изменены.

| Вопрос | Текущее поведение Frontend |
| --- | --- |
| Как связать восстановленный ошибочный ход с исходным вопросом? В GET нет `user_message_id`, `client_message_id` и `retryable` у хода. | После полученного `failed` повтор доступен при `retryable=true`. Исходный запрос и подтверждённые ID временно сохраняются в sessionStorage этой вкладки. Для неизвестного ошибочного хода повтор не угадывается. |
| Как воспроизводится завершённый запрос с тем же ID? | Ожидается SSE `accepted` → необязательные `status`/`delta` → `done` или `failed`, как указано в текущем контракте. |
| Гарантируется ли непрерывная нумерация `seq` с 1? | Повторные seq отбрасываются, пропуск приводит к GET-восстановлению. Для возобновления потока не используется Last-Event-ID. |
| Каковы максимальная длина вопроса, rate limits и формат Retry-After? | Пустой ввод отклоняется. Лимит длины не придуман на клиенте; 429 показывает серверное сообщение и возвращает текст в редактор. Изменяющие запросы автоматически не повторяются. |
| Какие Origin допустимы при разработке? Как работать с Secure cookie локально? | Vite proxy сохраняет Origin и проксирует `/api` и `/health`; рабочий стенд использует same-origin HTTPS. Cookie не читается и не переписывается JS. Нужна совместная проверка с реальным Backend. |
| Какие поля и типы поддерживает attributes? | Известные поля имеют русские подписи. Примитивы выводятся текстом, null и сложные значения обозначаются как требующие уточнения. Отдельные бейджи реестра/совместимости не выводятся по предположению. |
| Означает ли нулевая цена отсутствие подтверждённой стоимости? | null и ноль показаны как «Цена требует уточнения». Фактическая передача менеджеру не имитируется. |
| Что происходит со старой сессией и cookie при создании нового диалога/работе в нескольких вкладках? | Хранится один текущий UUID, новый диалог доступен без активного хода. Серверный 409 разрешается через GET. Списка диалогов и гарантии одновременной работы нескольких вкладок нет. |
| Есть ли рекомендуемые heartbeat и recovery-интервалы? | SSE ждёт до 120 с (выше начального серверного дедлайна 90 с). GET — до 15 с. Восстановление: 16 проверок с интервалом 1–5 с, затем ручная проверка. Клиент не объявляет серверный ход завершённым по своему таймеру. |
| Одинаково ли selection использует TURN_IN_PROGRESS и OFFER_CHANGED? | Выбор блокируется во время обработки; неизвестный результат операции сверяется через GET. Обновлённая карточка из OFFER_CHANGED требует явного подтверждения. |

## Особенность генерации типов

`openapi-typescript` теряет смысл required-only веток: Source с anyOf получается unknown,
а обязательный status сообщения из allOf остаётся optional. Кроме того, attributes без
additionalProperties генерируется как Record<string, never>.

`src/shared/api/types.ts` содержит небольшой адаптер этих трёх мест. Остальные DTO и тело
запроса генерируются напрямую. Runtime-проверки находятся в guards.ts. `pnpm api:check`
проверяет актуальность сгенерированного файла; при изменении указанных схем нужно также
проверить адаптер и тесты. Внешний контракт ради генератора не изменялся.

## Зафиксированный объём

- КП, счета и полноценный менеджерский интерфейс исключены решением команды.
- Поле quotes_enabled остаётся в типе сессии для совместимости; интерфейс документов не создаётся.
- Нагрузка для планирования — около 500 обращений за полгода.
- Срок готовности — 28 ноября 2026 года, 12:00 по Москве.
- Вопросы выше не препятствуют разработке и проверке Frontend с моками.
