## 26 ноября 2026 — FastAPI и RunPod

- Цель. Реализовать внутренний ML-сервис для Spring Boot по контракту команды и опубликовать его в ветке `fast_api_server` от пустой `main`.
- Начало работы. Сверены архитектура, внутренний OpenAPI и актуальная история журнала в `archit`. В `main` создан и опубликован пустой начальный коммит `d792c20`.
- В `contracts/internal.openapi.yaml` описаны `interpret`, потоковый `compose`, сервисная авторизация и локальные проверки состояния. Пример потока сохранён в `contracts/examples/internal-compose.sse`.
- В `ml-service/app/` добавлены модели Pydantic, промпты, клиент RunPod Serverless и маршруты FastAPI. `interpret` проверяет типы требований и цитаты из текущей реплики. `compose` выдаёт завершённые блоки со ссылками на факты из запроса. В первой версии общий лимит вызова FastAPI составлял 90 секунд и включал очередь. Проверки состояния модели не вызывают.
- В `ml-service/Dockerfile`, `infra/compose.ml.yaml` и `ml-service/.env.example` добавлены сборка, запуск в сети Compose и настройки профиля RunPod. Порядок запуска и примеры проверочных запросов описаны в `ml-service/README.md`. Контракт, реализация, тесты и сборка сохранены отдельными коммитами.
- Проверки. В `ml-service/` выполнены `uv run --locked --offline pytest -q` (20 успешно), `ruff check .` и `ruff format --check .`. Локальный запуск Uvicorn через Unix-сокет подтвердил ответы проверок состояния, авторизации и валидации. Команда `docker compose --env-file ml-service/.env.example -f infra/compose.ml.yaml config --quiet` прошла.
- Статус. Для проверки холодного и тёплого запусков нужны развёрнутый endpoint и ключ RunPod. Локальный Docker daemon был недоступен для сборки образа.

## 26 ноября 2026 — реализация бэкенда

- Цель. Поэтапно реализовать сессии, журнал, импорт каталога, поиск и SSE по контрактам команды.
- Начало работы. Проверены ветка, исходная миграция и контракты. Для реальных реплик сохраняем российский контур, для локальных проверок HTTP используем синтетические данные.
- Добавлены API сессий, журнал чата, резервирование и повтор хода, сверка предложений, импорт каталога и справки, HTTP-клиент ML и SSE. SQL добавляет сохранённую карточку и тип повтора к исходной схеме.
- Модельный поток используется для порядка подтверждённых фактов. Бэкенд публикует текст самих фактов и формирует карточки из каталога. При отказе `compose` продолжает ответ из проверенных данных.
- Сквозной прогон на PostgreSQL 17 и локальном имитаторе ML прошёл для сессий, поиска по полному фиду, справки, SSE, повтора без повторной реплики, выбора, таймаута, восстановления и сбоя `compose`. Сборка Spring Boot JAR на Java 21 и проверка формата Compose прошли.
- Отдельно проверены импорт всех 136 040 предложений, подбор по описанию задачи, смена версии XML на gzip, счётчики добавленных, изменённых и удалённых предложений, неизменившийся фид и сохранение прежнего снимка после отказа проверки.
- При задержке после первого SSE-блока обнаружено, что прерывание чтения закрывало JDBC-соединение перед сохранением статуса. Устранено в обработке дедлайна. Регрессионный прогон подтвердил `failed` в SSE и статус `partial` в журнале.
- Общий дедлайн под демо выставлен на 120 секунд в Java и Compose. Добавлен прогон `backend/tests/sse_timeout.py` с управляемой задержкой первого ответа или первого блока. Для него используется синтетическая HTTP-заглушка и отдельная временная БД.
- Финальная сборка `mvn -f backend/pom.xml --offline -B -ntp package` прошла на Java 21. Два независимых прогона с `--cold-delay 95` завершились за 95,2 секунды каждый. Проверены ожидание ответа `interpret`, ожидание первого блока `compose`, heartbeat и следующий быстрый ход. Эти результаты относятся к задержке, которую имитирует тестовый HTTP-сервис. Проверка реального холодного запуска на российском стенде остаётся частью интеграции.
