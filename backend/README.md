# Локальный бэкенд

Требуются Java 21, Maven и PostgreSQL. Из корня проекта запустите `mvn -f backend/pom.xml spring-boot:run`. Flyway создаёт таблицы и индексы при первом запуске. `/health/live` проверяет процесс. `/health/ready` возвращает `200`, когда в PostgreSQL доступен активный снимок каталога, и `503`, пока снимка нет или БД недоступна. При сбое обновления активный снимок предыдущей версии сохраняет статус готовности.

| Переменная | Значение или назначение |
| --- | --- |
| `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD` | Подключение к PostgreSQL. По умолчанию используется `jdbc:postgresql://localhost:5432/support`. |
| `CATALOG_FEED_FILE` | Путь к локальному XML или gzip. При запуске фид сразу проверяется. |
| `CATALOG_FEED_URL` | HTTPS-адрес фида для регулярной загрузки, когда локальный путь пуст. |
| `CATALOG_SYNC_CRON`, `CATALOG_SYNC_ZONE` | Расписание проверки. По умолчанию каждый день в 04:00 по Москве. |
| `CATALOG_KNOWLEDGE_FILE` | JSON с утверждёнными выдержками из справки. |
| `CHAT_PUBLIC_ORIGIN` | Точные разрешённые origin через запятую, по умолчанию `http://localhost:8080`. Каждый изменяющий запрос проверяется по заголовку `Origin`. |
| `ML_BASE_URL`, `ML_DATA_REGION`, `ML_SERVICE_TOKEN` | Внутренний HTTP-адрес FastAPI, подтверждённый регион `RU` и сервисный токен. При пустом адресе модельные ходы завершаются с возможностью повтора. |
| `ML_MAX_CONTEXT_BYTES` | Ограничение запроса к FastAPI в байтах UTF-8, по умолчанию 24 000. Для длинного диалога первыми исключаются самые старые реплики. Значение задаётся одинаково для Java и FastAPI. |
| `CHAT_TURN_TIMEOUT_MS`, `CHAT_COLD_TURN_TIMEOUT_MS` | Общий бюджет обычного хода — 90 секунд, холодного — 180 секунд. |
| `CHAT_MODEL_IDLE_MS`, `CHAT_PARALLEL_TURNS` | Пауза для повторного выбора холодного бюджета — 15 секунд, предел параллельных ходов — 8. |
| `CHAT_DISCOUNT_PERCENT` | Процент для явного возражения о цене и подтверждённого отсутствия купона. По умолчанию 5, диапазон 0–5. Значение 0 отключает предложение скидки. |
| `MANAGER_ACCESS_TOKENS` | Демо-доступ к очереди. Список пар `идентификатор=токен` через запятую. Пустое значение означает, что менеджерский API не авторизует запросы. |

Ход становится доступен после активации первого проверенного снимка. Пока снимка нет, API сообщений возвращает `503 CATALOG_UNAVAILABLE`. Для локальной проверки публичного контракта и SSE используйте синтетические реплики. Для браузера cookie требует HTTPS, а тестовый HTTP-клиент может передать её явно.

`interpreting` приходит в начале ожидания модели. Пока ход выполняется, SSE отправляет heartbeat примерно каждые 8 секунд. Бэкенд использует холодный бюджет при первом обращении после запуска и после паузы с последнего успешного ответа FastAPI. Это локальная оценка прогрева. Для каждого хода дедлайн включает поиск и оба вызова ML. FastAPI получает оставшееся время через `deadline_ms`. Таймауты FastAPI, модели, внешнего прокси и браузера нужно сверить с этими бюджетами на стенде.

Строка `Chat turn timing` связывает новый ход с `request_id` и `turn_id`. В ней есть выбранный бюджет, длительность `interpret`, поиска и чтения потока `compose` в миллисекундах, время до отправки первого `delta` из Java, общая длительность и итог. `null` означает, что этап не выполнялся или итоговое поле неприменимо. При ответе из подтверждённых фактов после сбоя `compose` выставляется `compose_fallback=true`. Повторы с уже сохранённым результатом не добавляют второй замер. Тексты сообщений и секреты в эту строку не попадают.

Файл знаний содержит массив документов. Каждый документ задаёт `source_url`, `title`, `fetched_at` с часовым поясом, `version` и массив `chunks` с полями `section` и `text`. Повтор с той же версией и содержанием идемпотентен. Для обновления материала используйте новую версию. Источниками служат утверждённые разделы справки и магазина.

В рабочем контуре PostgreSQL, его резервные копии, Java, FastAPI и модель, получающая тексты чата, размещаются в РФ. `ML_DATA_REGION=RU` — подтверждение оператора конфигурации, которое проверяется при запуске. Оно предполагает проверенное размещение окружения. Полные реплики хранятся в журнале чата в PostgreSQL. Срок хранения предстоит согласовать с заказчиком.

Для совместного запуска используйте корневой `compose.yaml` и общий `ML_SERVICE_TOKEN`. В конфигурации Java укажите `ML_BASE_URL=http://ml-service:8000`. [Запуск через Compose](../infra/README.md) · [Настройки FastAPI](../ml-service/README.md)

Проверка частичного SSE запускает локальный HTTP-имитатор ML и JAR. Используйте отдельную пустую БД PostgreSQL для синтетических данных.

```sh
mvn -f backend/pom.xml package
python3 backend/tests/sse_timeout.py --jdbc-url jdbc:postgresql://127.0.0.1:5432/support_test
```

В расширенном прогоне `--cold-delay 125` имитирует холодный ответ `interpret` через 125 секунд. Проверяются heartbeat, фактический замер задержки и смена бюджетов 180 → 90 → 180 секунд. Для задержки первого текстового блока после открытия потока FastAPI добавьте `--cold-stage compose`. Прогон без задержки холодного старта использует короткий дедлайн и проверяет замеры для `TURN_TIMEOUT` с сохранением частичного ответа.

## Обращения к менеджеру

Явную просьбу проверить документы или возможность поставки вне витрины Java передаёт в очередь без вызова модели. Если модель распознала запрос на известный товар и Java не нашла доступных кандидатов, она также создаёт обращение. Менеджер проверяет возможность поставки, условия и перечень необходимых документов. Пока обращение открыто, последующие сообщения клиента пополняют тот же диалог.

Для демо назначьте каждому менеджеру свой случайный токен. Для генерации подходит `openssl rand -hex 32`. Укажите пары `manager_id=token` через запятую в секретах развёртывания или локальном `.env`. Кабинет передаёт `Authorization: Bearer <token>`. При удалении или замене токена вызовы со старым токеном прекращаются после перезапуска Java. Для HTTPS-стенда токены передаются по защищённому каналу и вводятся пользователями кабинета при подключении. [Контракт кабинета](../contracts/manager.openapi.yaml)

Менеджер видит общую очередь и свои обращения. После назначения он может читать переписку, отправлять сообщения и закрыть обращение. Для клиентского фронта `GET /api/v1/sessions/{session_id}/handoff` возвращает статус, а `GET` сессии возвращает ответы менеджера с `role=assistant` и `sender=manager`. Оба ответа можно опрашивать, пока обращение открыто. [Контракт кабинета](../contracts/manager.openapi.yaml)

Для проверки на пустой тестовой БД запустите Java с активным тестовым каталогом и двумя отдельными менеджерами в `MANAGER_ACCESS_TOKENS`. Передайте ту же переменную сценарию `python3 backend/tests/manager_handoff.py --origin http://127.0.0.1:8080`.

## FAQ из ответов менеджеров

Кандидат создаётся при закрытии обращения с ответом. Состояние доступно через `GET /api/v1/manager/handoffs/{handoff_id}/faq`, в том числе с параметром `source_query` для поиска актуальной выдержки. Действия `approve`, `reject` и `unpublish` принимают тот же менеджерский Bearer-токен. [Контракт кабинета](../contracts/manager.openapi.yaml)

В `infra/.env.example` фоновая проверка включена через `FAQ_REVIEW_ENABLED=true` для Compose со связкой Java и FastAPI. При запуске с собственным `.env` включите этот флаг и проверьте доступность `POST /internal/v1/faq/review` с сервисным токеном. Бюджет одного вызова задаётся `FAQ_REVIEW_TIMEOUT_MS` и по умолчанию равен 30 секундам. Java делает до трёх попыток с паузами в одну и две минуты. [Контракт Java ↔ FastAPI](../contracts/internal.openapi.yaml)

Для сквозной проверки соберите JAR и запустите `python3 backend/tests/faq_review.py --compose-file /tmp/faq/compose.yaml`. Используйте отдельный пустой PostgreSQL 17 в сервисе `postgres` с портом `127.0.0.1::5432`, БД и пользователем `faq_check`, тестовым паролем `faq_check_fixture`. Сценарий запускает собственную Java и HTTP-подмену FastAPI.

## Коммерческое предложение

Для локального запуска включите `CHAT_QUOTES_ENABLED=true` в конфигурации Java или в корневом `.env` для Compose. Владелец сессии выбирает позицию через `selection` и передаёт название организации и количество позиций в `POST /api/v1/sessions/{session_id}/quote-drafts`. Ответ содержит `quote.pdf` на основе шаблона ПАО «Софтлайн» с идентификатором КП и таблицей предложения. Название, артикул, цена и валюта берутся из действующего каталога. Позиция с ценой оформляется и при `available=false`. Java сохраняет исходную цену, скидку, количество и итог версии КП. При изменении позиции сервер возвращает `OFFER_CHANGED` для повторного подтверждения. Поля НДС, оплаты, поставки и срока действия оставлены менеджеру. [Публичный OpenAPI](../contracts/public.openapi.yaml)

### Счёт по одобренному КП

Включите `CHAT_QUOTES_ENABLED=true` и `CHAT_INVOICE_DRAFTS_ENABLED=true`. Сформируйте КП, возьмите его идентификатор из заголовка `X-Quote-Id` и одобрите условия запросом `POST /api/v1/sessions/{session_id}/quote-drafts/{quote_id}/approval`. Для счёта отправьте `POST /api/v1/sessions/{session_id}/invoice-drafts` с JSON `{"quote_id":"<UUID из X-Quote-Id>"}`. Для всех запросов используются cookie владельца и допустимый `Origin`.

Первая выдача сверяет позицию с каталогом и использует сохранённый итог КП. В `invoice.pdf` указываются основание, покупатель, согласованная позиция, сумма и реквизиты ПАО «Софтлайн». При изменении условий сформируйте и одобрите новое КП.

Для тестового выпуска задайте `CHAT_TEST_PAYMENT_INVOICES_ENABLED=true`. PDF получит заголовок «Счёт на оплату», номер `TEST-…` из PostgreSQL и пометку о тестовом выпуске. Назначение указывается в `X-Invoice-Purpose`, номер передаётся в `X-Invoice-Number`. При выключенном флаге новые документы оформляются для согласования. Повтор для выданного `quote_id` сохраняет PDF, назначение и номер. [Публичный OpenAPI](../contracts/public.openapi.yaml)
