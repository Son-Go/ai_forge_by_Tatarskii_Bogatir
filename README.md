# Консультант Softline

Веб-консультант по подбору и покупке программного обеспечения из каталога Softline. Клиент может назвать продукт или описать задачу, получить подходящие предложения и задать вопрос об оплате, совместимости или уже купленной лицензии. Чат показывает карточки и ссылки на источники, а при необходимости передаёт разговор менеджеру.

## Возможности

- Подбор по продукту, артикулу или задаче с учётом числа пользователей, срока и типа лицензии. Для неподтверждённых характеристик чат показывает, что нужно уточнить.
- Справочные ответы по каталогу, материалам Softline Store и опубликованным ответам FAQ. Вопрос о другом продукте сохраняет условия текущего подбора.
- Кабинет менеджера с очередью, историей и ответом в том же диалоге. Проверенные общие ответы менеджера можно публиковать в FAQ.
- PDF коммерческого предложения по выбранной позиции. После одобрения доступен счёт для согласования или тестовый счёт на оплату с номером `TEST-…`. Повторное скачивание выдаёт сохранённый документ.

## Как это работает

React отправляет сообщение в Spring Boot. FastAPI с моделью Qwen3-32B помогает понять запрос и извлечь требования. Java ищет предложения и справку в PostgreSQL, проверяет характеристики, рассчитывает сумму и определяет, когда передать разговор менеджеру. В браузер ответ приходит по SSE вместе с карточками и источниками.

Каталог загружается из фида Softline. В интеграционном прогоне использовали снимок на 135 633 позиции и модель `softline-lora` на RunPod Serverless через vLLM. Адрес модели настраивается при развёртывании. Для типовой рекомендации Java сама формирует короткий ответ после интерпретации запроса. [Подробная архитектура](ARCHITECTURE.md)

## Запуск

### Демонстрация интерфейса

Для просмотра чата и кабинета на синтетических данных нужны Node.js и pnpm. Поддерживаемые версии указаны в [инструкции фронтенда](frontend/README.md).

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev:mock
```

Откройте [локальный интерфейс](http://127.0.0.1:5173). Для запуска нужны только зависимости фронтенда.

### Полный локальный стенд

Нужны Docker с Compose, источник каталога и настроенный профиль модели. Из корня репозитория скопируйте пример окружения, если локального файла ещё нет.

```sh
test -f .env || cp infra/.env.example .env
```

Задайте отдельные пароли PostgreSQL и Grafana. Укажите URL фида в `CATALOG_FEED_URL` или подключите файл через `CATALOG_FEED_FILE`. Параметры подключения Java к FastAPI и тестовому профилю модели описаны в [инструкции запуска](infra/README.md) и [настройках FastAPI](ml-service/README.md).

Для входа в кабинет настройте `MANAGER_ACCESS_TOKENS`. Для проверки КП и счёта включите `CHAT_QUOTES_ENABLED` и `CHAT_INVOICE_DRAFTS_ENABLED`. Тестовый выпуск счёта на оплату включается отдельно через `CHAT_TEST_PAYMENT_INVOICES_ENABLED`. [Настройки Java](backend/README.md)

```sh
docker compose config --quiet
docker compose up -d --build
curl --fail http://localhost:8080/health/ready
```

`/health/ready` вернёт HTTP 200 после импорта активного снимка. При стандартных портах откройте [чат](http://localhost:8080/), [кабинет менеджера](http://localhost:8080/#/manager) или [Grafana](http://127.0.0.1:3000/).

## Что проверить

1. Напишите «Подбери MDaemon на 20 пользователей». Откройте карточки и проверьте, что чат указывает подтверждённые условия и источники.
2. Спросите «Для какой ОС подходит The Bat! Professional?», затем вернитесь к подбору MDaemon. Чат должен переключить предмет справочного ответа и сохранить прежнее количество.
3. Напишите «Ключ не пришёл», затем «Не помогло». Чат сначала даст инструкцию, а потом в кабинете менеджера появится обращение с историей.
4. Выберите позицию с ценой и сформируйте КП. При включённой выдаче документов одобрите КП и скачайте счёт. Повторное скачивание должно вернуть тот же документ.

В приёмке `fast_api_v5` прошли 7 сквозных сценариев в Chrome с живым `softline-lora` на тестовых сообщениях. На отдельном контрольном наборе прошли 29 проверок интерпретации и 2 проверки сборки ответа из подтверждённых фактов.
